Big-O Basics

Big-O describes how an algorithm's time or space needs grow as input size n grows. It's a ceiling on growth rate, not an exact timer — useful for comparing approaches, not measuring seconds.

Arrays

An array stores elements in contiguous memory, so any index can be read in O(1). Inserting or deleting in the middle costs O(n) because later elements must shift.

Singly Linked Lists

Each node holds a value and a pointer to the next node. There's no contiguous memory, so random access is O(n) — but inserting at the head is O(1) since nothing needs to shift.

Searching

Linear search checks every element — O(n) — and works on any array. Binary search repeatedly halves a sorted array — O(log n) — but requires the array be sorted first.

Binary Search Trees

In a BST, every left subtree holds smaller values and every right subtree holds larger ones, so search, insert, and delete average O(log n) on a balanced tree (worst case O(n) if it degenerates into a line).

Graphs — BFS & DFS

Breadth-First Search explores level by level using a queue (great for shortest paths on unweighted graphs). Depth-First Search dives down one path using a stack/recursion before backtracking.

Graph Algorithms — Dijkstra's Shortest Path

Dijkstra's algorithm finds the shortest path from a start node to every other node in a weighted graph, as long as all edge weights are non-negative. It repeatedly picks the closest unvisited node, finalizes its distance, and relaxes (updates) its neighbors' tentative distances — similar in spirit to BFS, but weight-aware.

How it works

  1. Set the start node's distance to 0, and every other node's distance to infinity (unknown).
  2. Pick the unvisited node with the smallest known distance — the first time, that's the start node.
  3. For each of its neighbors, check whether going through this node gives a shorter path than what's currently known (this check is called relaxing the edge). If so, update that neighbor's distance and remember which node it came from.
  4. Mark the current node as visited/finalized — its distance can never improve after this.
  5. Repeat from step 2 until every reachable node has been visited.
  6. To read off the shortest path to any node, walk backward through the "came from" pointers to the start.
function dijkstra(graph, start):
    dist[start] = 0
    dist[every other node] = infinity
    prev[every node] = none
    unvisited = all nodes

    while unvisited is not empty:
        u = the unvisited node with smallest dist[u]
        remove u from unvisited

        for each neighbor v of u:
            alt = dist[u] + weight(u, v)
            if alt < dist[v]:
                dist[v] = alt      # relax the edge
                prev[v] = u

    return dist, prev

Dijkstra requires non-negative edge weights. If a graph can have negative weights, use Bellman-Ford instead; if you have a good estimate of distance to a known target, A* often outperforms plain Dijkstra.

Minimum Spanning Tree — Prim's Algorithm

A minimum spanning tree (MST) connects every node in a weighted graph using the smallest possible total edge weight, with no cycles. Prim's algorithm grows one MST by always grabbing the cheapest edge that reaches a new node — greedy, like Dijkstra, but optimizing total tree weight instead of per-node distance from a source. It's the same graph as the Dijkstra tab, so you can compare a shortest-path tree against a minimum spanning tree on identical data.

How it works

  1. Start with a tree containing just one node.
  2. Look at every edge that connects a node already in the tree to a node that isn't yet.
  3. Pick the cheapest such edge, and add its new node (and that edge) to the tree.
  4. Repeat until every node has joined the tree.
  5. The edges collected form a minimum spanning tree — the cheapest way to connect every node.
function prim(graph, start):
    inTree = {start}
    mstEdges = []

    while inTree does not contain every node:
        find the cheapest edge (u, v) where
            u is in inTree and v is not
        add v to inTree
        add edge (u, v) to mstEdges

    return mstEdges

Prim's grows one connected tree outward from a start node — good for dense graphs. Kruskal's instead sorts all edges and adds the cheapest ones that don't form a cycle — often simpler for sparse graphs. Both always produce a valid MST (the total weight is unique, though the exact edge set can differ when weights tie).

Hash Maps

A hash map converts a key into a bucket index via a hash function, giving O(1) average-case get/set/delete. When two keys hash to the same bucket — a collision — this demo chains them together in a small list, so that bucket degrades toward O(n).

Bucket count: 8. Hash = sum of character codes mod bucket count.

Heaps

A binary heap is a complete binary tree stored as a flat array, where every parent is smaller than its children (min-heap) or larger (max-heap). That invariant makes the root always the min/max, so peeking is O(1) while insert and extract cost O(log n) to restore the shape.

Tries (Prefix Trees)

A trie stores strings character by character along shared paths, so words with common prefixes share nodes. Insert, exact-word search, and prefix search all run in O(L) time, where L is the length of the word — independent of how many words are stored.

Recursion & Dynamic Programming

Recursion solves a problem by calling itself on smaller subproblems until a base case is reached, then combines results as calls return — tracked on the call stack. Dynamic programming speeds this up when subproblems overlap, by solving each one only once: top-down with a memo cache, or bottom-up by filling a table iteratively.
